# ロードマップ

優先順位は「元画像を失わない」「判定結果を追跡できる」「人間の確認を減らす」の順です。自動削除や WAN 公開は対象外です。

## 初版（最小実用品）

- [x] Windows 11 + Python 3.11 の実行手順
- [x] ローカル／UNC 入力パス
- [x] `scan` による一括処理
- [x] `watch` による新規画像の監視
- [x] PNG/JPEG/WebP とサブフォルダ
- [x] LM Studio OpenAI 互換 API への画像送信
- [x] ChatGPT認証済みCodex CLIによるGPT-5.6 Luna判定
- [x] APIキー認証を画像送信前に拒否する料金保護ガード
- [x] JSON Schema固定出力、read-only、エフェメラル実行
- [x] JSON 固定出力の検証・補正・再試行
- [x] ローカル安全ルールによる PASS/REVIEW/FAIL の再評価
- [x] copy/move の仕分け
- [x] JSONL/CSV ログ
- [x] サムネイル付き静的 `review.html`
- [x] `rescan-review`、`build-report`、`test-lmstudio`
- [x] 実画像1枚を使ったCodex CLI / GPT-5.6 Lunaスモークテスト
- [x] WindowsデスクトップGUI（バックエンド／モデル／推論設定、接続確認）
- [x] GUIの一括スキャン、継続監視、進捗・結果・ログ、協調的停止
- [x] 判定基準プリセット（緩め／標準／厳格）とアニメ調・誇張・重なりを許容する標準プロンプト
- [x] モデル生判定、最終判定、判定源、ルール根拠のJSONL／CSV／GUI表示
- [ ] 実UNC・実LM Studioを使った環境別スモークテスト（運用側で実施）

## 次の優先候補

1. ファイル安定化待ちと、ネットワーク切断時のバックオフ
2. 仕分け先での同名衝突・再実行ポリシーの明示
3. 結果履歴とモデル／プロンプト／設定の記録強化
4. 失敗画像の再試行キューと API 障害／JSON 不正の可視化
5. `review.html` の検索、キーボード操作、元画像を開くリンク、手動ラベル
6. 画像ハッシュによる重複判定と、キャッシュの安全な期限管理
7. 並列処理の上限・GPU メモリ監視・レート制限

## 中期候補

- 顔／手クロップ再判定（[CROP_RECHECK_DESIGN.md](CROP_RECHECK_DESIGN.md)）
- フル画像とクロップ判定を統合したスコアカード
- ルールセットのバージョン管理と A/B 評価
- 人手ラベルを使った閾値校正、誤検知／見逃しの集計
- EXIF、生成プロンプト、seed、モデル情報の保持
- SQLite などのローカルインデックス（JSONL は引き続きエクスポート）
- ローカル API（必要性が明確になった場合のみ。認証・LAN 制限を前提とする）

## 長期候補

- 複数 VLM の投票または専門モデル（顔、手、NSFW 等）の組み合わせ
- 画像類似度による代表画像選択
- 大量バッチの再現可能なジョブ定義と中断／再開
- 計測データに基づくモデル選定・量子化選定

## 非目標・安全制約

- 初期版での自動削除、ゴミ箱を迂回する削除、不可逆な一括移動
- API、SMB、SSH などの WAN 公開
- VLM の出力だけで重要な判断を確定すること
- 実行中の BIOS／ファームウェア／Windows Firewall 全体設定の変更

## 完了条件の目安

機能を追加するときは、少なくとも次を満たすことを目標にします。

- 元画像を保持したまま再実行できる
- `results.jsonl` から入力・モデル・設定・判定・エラーを追跡できる
- LM Studio が停止／不正 JSON／タイムアウトしてもプロセス全体が落ちない
- ローカルパスと UNC パスの両方で同じ判定契約が成立する
- unit test と少数画像の手動スモークテストが通る
